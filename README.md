# ツミクエスト (Tsumi-Quest)

**積まれたゲームは、あなたが挑むべきクエストだ！**

「ツミクエスト」は、増え続ける積みゲーをRPG感覚で楽しく消化することを目指したWebアプリケーションです。

ゲームのプレイ時間やクリア状況に応じて経験値を獲得したり、条件を達成してトロフィーを収集したりすることで、積みゲーを消化する過程そのものを楽しめる体験を提供します。

## 制作背景

ゲームを購入したものの、なかなか遊ぶ時間が取れず、積みゲーが増えてしまうことがあります。

私自身もそのような経験があり、積みゲーを単なる管理対象として扱うのではなく、RPGのクエストをクリアしていくような楽しさに変えられないかと考え、開発を始めました。

そこで、次の2つを重視して設計しました。

- **プレイするきっかけを作る：** ゲームのプレイ時間に応じて経験値を獲得できるようにし、ゲームを遊ぶこと自体がモチベーションにつながる仕組みを取り入れました。
- **クリアする達成感を高める：** ゲームをクリアすると固定の経験値報酬を獲得できるようにし、最後まで遊び切ることにも報酬を設けました。

単にゲームの進行状況を記録するだけでなく、ゲームを遊ぶことやクリアすることに楽しさを加えることを目指しています。

## 主な機能

### ゲーム管理
- IGDB APIと連携したゲームタイトル検索・サジェスト
- ゲーム情報・パッケージ画像の自動取得
- ゲームの購入時期、プレイ期間、プレイ時間、評価、メモの記録
- 「未プレイ」「プレイ中」「クリア済」などのステータス管理
- Active Storageによるオリジナル画像のアップロード

### RPG要素
- プレイ時間に応じた経験値の獲得
- ゲームクリア時の固定経験値報酬
- 経験値に応じたレベルアップ
- トロフィーの獲得
- ゲームの開始・クリア履歴を記録するアクティブログ

### その他
- Clerkによるユーザー認証
- DeepL APIによるゲームあらすじの日本語翻訳

## 開発で工夫したこと

### 1. ゲーム検索機能のパフォーマンス改善

ゲーム検索機能の実装当初、検索候補が表示されるまでに約8秒かかる問題がありました。

原因を調査したところ、検索候補の取得時に、ゲームのあらすじを毎回DeepL APIで翻訳していたことが分かりました。

そこで、翻訳処理を検索時ではなく、ユーザーがゲームの保存を確定したタイミングで実行するように変更しました。これにより、検索時に不要な翻訳処理を行わずに済むようになり、表示時間を約2秒まで短縮しました。

さらに、検索速度を改善するため、Amazon ElastiCache for Redisによるキャッシュを導入しました。

IGDB APIから取得したゲームの基本情報・詳細情報をRedisにキャッシュし、再検索時にはキャッシュから情報を取得する仕組みに変更しました。
その結果、キャッシュ利用時のサジェスト表示時間を約20msまで短縮し、同じゲームに対する不要な外部API通信も抑制しました。

**改善結果**

| 状態 | サジェスト表示時間 |
| :--- | ---: |
| 改善前 | 約8秒 |
| 翻訳処理のタイミング変更後 | 約2秒 |
| Redis導入後（キャッシュ利用時） | 約20ms |

### 2. 過去のゲーム記録にも価値を持たせるトロフィー機能

経験値機能は、現在またはこれからプレイするゲームのプレイ時間やクリアによって獲得する仕組みです。しかし、アプリの利用開始前にクリアしたゲームを登録しても、経験値は獲得できません。

そこで、過去にクリアしたゲームの登録にもメリットを持たせたいと考え、トロフィー機能を実装しました。

累計クリア本数などの条件を達成するとトロフィーを獲得できるようにすることで、過去のゲーム実績も評価対象にしています。

これにより、これからプレイするゲームだけでなく、これまで遊んできたゲームも登録してコレクションしていく楽しさを提供しています。

### 技術選定理由

| 技術 / サービス | 選定理由 |
| :--- | :--- |
| **Terraform (IaC)** | AWSリソース（VPC、ECS、RDS、ElastiCache等）の構築をコード化し、再現性を担保するため。非稼働時は独自ドメインのネームサーバー設定を維持する Route 53 ホストゾーン（`prevent_destroy`）のみを残し、課金リソースを `-target` 指定で選択的に停止・再構築することで待機コストを最小化しています。 |
| **GitHub Actions (CI/CD)** | `main` ブランチへのマージをトリガーに、Dockerイメージのビルド・ECRへのプッシュ・ECSへのデプロイを自動化するため。また、ALBを省いた最小構成で発生する「タスク再起動ごとのパブリックIP変動」を解消するため、デプロイ後にAWS CLIで最新IPを動的取得し Route 53 のAレコードを自動更新（`UPSERT`）する処理を実装しています。 |
| **Amazon ECS (Fargate)** | EC2のOS管理やパッチ適用などのサーバー運用負荷を省き、コンテナベースでアプリケーションを安定稼働させるため。 |
| **Amazon RDS (PostgreSQL)** | ユーザー情報、ゲーム記録、トロフィーなどの永続データを安全に管理するため。インターネットから隔離されたプライベートサブネットに配置しています。 |
| **Amazon ElastiCache (Redis)** | 外部API（IGDB API）のレート制限回避と検索サジェストの高速化のため。検索クエリの正規化（前後空白削除・小文字統一）とあわせて検索結果をキャッシュし、2回目以降の応答時間を約350msから約5msまで短縮しました。 |
| **Amazon S3 / CloudFront** | Active Storageでアップロード・取得したゲームカバー画像をアプリケーションサーバーから分離し、CDN経由で高速配信することでECSへの負荷を軽減するため。 |
| **VPC / Security Group** | 月額固定費の高いNAT GatewayやALBを省きコストを最適化しつつ、データストア層（RDS / ElastiCache）をプライベートサブネットへ分離するため。Security GroupによりECSからの特定ポート通信のみを許可しています。 |
| **SSM Parameter Store** | DB認証情報や外部APIキーなどの機密情報をソースコードやリポジトリに一切残さず、`SecureString` として暗号化・一元管理するため。 |

## AIを活用した開発プロセス

個人開発において、Gemini ProとGitHub Copilotを活用しています。

- **Gemini Pro：** 企画・要件定義、技術調査、実装方針の検討、タスク分割などに利用。
- **GitHub Copilot：** コードの実装や修正に利用。

開発では、大きな機能を一度に実装させるのではなく、Geminiを活用してタスクを小さな単位に分割するようにしています。

その後、GitHub Copilotで個別のタスクを実装し、コードを確認しながら段階的に進めています。小さな変更を積み重ね、Pull Requestを通じてmainブランチに統合することで、一度に確認するコード量を抑え、実装内容の理解が不十分なまま開発が進むことを防ぐようにしています。
